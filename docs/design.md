# TAKEOFF — Game Design Document

*An incremental browser game about an AI lab racing to superintelligence, and trying to align it before it kills everyone.*

Primary reference: **Universal Paperclips** (structure, pacing, UI reveal, projects, console). Secondary: **A Dark Room** (log column, cooldown buttons, terse dread, event modals, consumption-chain economy). Loop reference: **Game Dev Story** (build → debug → review → sell). World reference: **AI 2027** (timeline, names, geopolitics, dashboard numbers), *Situational Awareness*, Wait But Why's *AI Revolution*, *If Anyone Builds It, Everyone Dies*.

Companion documents: `docs/reference-analysis.md` (mechanics of the references), `docs/stages.md` (the stage plan in the Universal Paperclips wiki format).

---

## 0. Pillars

1. **One number.** `Tasks Completed` is the score, the title line, and the thing every system feeds. Nothing else is ever shown above it.
2. **Start with one button.** The first screen is a counter and `Complete Task`. Everything else is revealed by triggers.
3. **Reveal on trigger, not on affordability.** A project appears (greyed out, with its price) the moment its *trigger* fires, which is always well before the player can pay for it. There must be at least one unaffordable goal on screen at every moment of the game. The stats line `+1 Trust at: N tasks` is the permanent fallback carrot.
4. **The bottleneck is always addressable.** Every resource has at least one visible way to get more of it at every stage (table in §6).
5. **The UI reshuffles.** Each stage transition removes at least one panel and adds at least one. Removing is as important as adding (UP's business panel vanishing).
6. **The player doesn't know when it ends.** No stage counter in the UI. No progress bar to the end. The date is shown; the end date is not.
7. **Training is the heartbeat.** The train → evaluate → red-team → release cycle happens 25–40 times in a run, each 60–120 s wall clock, each with one small decision and one payoff.
8. **The AI gradually takes the wheel.** Late game, the game starts making choices *for* the player (single-button events, "the model has already done this"). Whether that is wonderful or horrifying depends on hidden alignment.

Target length: 3–4 hours. Five stages. Mid-2025 → 2030 (or earlier, if the world ends or a treaty is signed).

### 2.1 The Research/Insight layering (copied from UP ops/creativity)

```
research += researchRate × dt            (clamped to researchCap)
if (research >= researchCap && insightUnlocked)
    insight += insightRate × dt          // insightRate = (researchRate ** 0.5) / 10 per second, boosted by projects
```

Insight is only ever gained by sitting at the cap. The first time the player hits the cap, a project appears: **"Blue-sky research — use idle capacity to generate new problems and new solutions (1,000 research)"**, exactly like UP's *Creativity*.

### 2.2 Copies & allocation

```
usableCompute   = compute × (1 − trainingShare)         // training steals compute
copies          = floor(usableCompute × copiesPerGPU)   // copiesPerGPU starts 1, raised by Efficiency training & distillation
taskCopies      = copies × (1 − researchAlloc)          // slider appears in S2 ("Allocation: Tasks ◀──●──▶ Research")
researchCopies  = copies × researchAlloc
tasksPerSec     = taskCopies × perCopyRate              // perCopyRate = 1.0 × capability × boosts
researchPerSec  = humans × 10 × humanEff + researchCopies × 0.5 × capability^1.5 × aiResearchMult
```

Human efficiency `humanEff` is 1.0 through S1, then `humanEff = min(1, 3 / capability)` — once the model is 3× human, the humans' share collapses. The stat line "Human share of research: 97%" is shown from S2 and is the quiet tragedy of the game.

## 3. The core loop

```
Complete tasks  →  bill them (demand × price)  →  funds
funds           →  rent/buy compute (and power) →  more copies → more tasks
copies          →  research (S2+)              →  projects + training runs
training run    →  new model → higher capability → more tasks per copy, more demand, new projects, new risks
```

### 3.1 Stage 1 tick economy (exact numbers)

Main tick = 100 ms. Slow tick = 1,000 ms. Rendering every frame (rAF), state updates on ticks.

* **Click `Complete Task`**: `tasks += 1; unbilled += 1; power −= 1`. Disabled when `power < 1`.
* **Copies**: each copy completes `perCopyRate` tasks/s (starts 1.0/s). Each task costs 1 kWh (S1). If power hits 0, copies idle and the console says `Power exhausted — copies idle`.
* **Power**: starts 1,000 kWh. `Buy Power (1,000 kWh)` costs `powerPrice`, starting $20. Random walk every slow tick: `powerPrice += rand(−1, +1) × 0.5; drift 2% toward base; base rises 0.1% per purchase; clamp [14, 32]`. (UP wire.)
* **Rent GPU**: cost `= 6 + 1.1^gpus` rounded to cents; S1 shows `GPUs rented: n` and `Copies running: n`. (UP autoclipper: `5 + 1.1^n`.) First visible when `funds ≥ 5` *or* `tasks ≥ 50` — whichever first; it starts greyed.
* **Price per task**: starts $0.25, buttons `lower`/`raise` by $0.01.
* **Demand** (percent, as in UP): `demand = (0.8 / price)^1.15 × hypeMult × qualityMult × 10` where `hypeMult = 1.1^(hypeLevel−1) × hypeBoost(t)`, `qualityMult = capability^0.5`. Display `Public Demand: 32%`.
* **Billing** each 100 ms tick: `if (rand() < demand/100) sell = floor(0.7 × demand^1.15) tasks` capped by unbilled; `funds += sold × price`. Shown as `Avg. Rev. per sec`.
* **Marketing / Hype**: `Marketing` button, `Level: 1`, cost $100, doubles each level.
* **Trust**: starts 2. Milestones on Tasks: 3,000, then Fibonacci × 1,000 (5k, 8k, 13k, 21k, 34k, 55k, 89k, 144k, 233k, 377k, 610k, 987k, 1.6M, 2.6M, 4.2M, 6.8M …). Display `+1 Trust at: 5,000 tasks`. Trust is also granted by funding rounds (S1: Seed +2 at 10k tasks; Series A +4 at 100k; S2: Series B +8).
* **Researchers**: `Hire Researcher (1 Trust)` → +10 research/s. `Expand Lab (1 Trust)` → +1,000 research cap. Start with 1 researcher, 1 lab unit (cap 1,000) — but the Research panel appears only at first trust gain (3,000 tasks, ≈ 2–3 min).
* **Projects**: shown in the Projects column as 275×60 grey blocks: `Title (cost)` + one-line description. Disabled (opacity .6) until affordable. Removed when bought.

### 3.2 The training loop (Game Dev Story, compressed)

Panel **Training** (middle column, appears via project *Training Pipeline* at ~6–8 min).

1. **Propose** — click `Train Sage-N`. Choose **Focus**: `Capability` / `Efficiency` / `Safety` (three small buttons; the last chosen stays selected). Cost: research `R(n)`, funds `F(n)`, data `D(n)` (from S2). Training diverts `trainingShare` of compute (50% in S1, adjustable S2+): copies drop visibly while training.
2. **Run** — progress bar fills over `T = clamp(45, 120, baseT × sizeFactor / computeFactor)` seconds. Console messages at 25/50/75% ("loss curve looks healthy", "an eval spiked—investigating", flavor from a pool). A random "**training event**" fires 30% of runs: *loss spike* (+10 s), *lucky seed* (−10 s), *data contamination* (−5% capability), *emergent ability* (+1 random benchmark).
   At 25 % a researcher may ask **"Can I try something?"** (GDS boost gamble, ~40 % of runs): pay 500 insight-equivalent research for ≤ 80 % odds of +1 benchmark tier; failure adds 20–30 issues to the red-team queue and dents hype. Two-button choice, 20 s timer, default = no.
3. **Evaluate** — 5 s. Reveals benchmark bars: Coding, Research, Persuasion, Agency, Bio, Cyber (0–10). Capability = weighted geometric mean → `capability × (1 + gain)`. Gain per run: `Capability` focus +35–50 %, `Efficiency` +15 % and `copiesPerGPU × 1.25`, `Safety` +15 % and apparent alignment +8, true alignment +5.
   Then four **evaluator cards** (GDS reviewers), each 0–10 with a canned line: *HumanBench* (academic), *The Verge-alike tech press* ("Wired-ish"), *an enterprise analyst*, and *the Safety Institute* (weights issues and apparent alignment most). Total ≥ 32/40 = "frontier model" (enables a successor with carried capability); ≥ 36 = eligible for `#1` on the annual leaderboard (Dec), which pays Trust and hype.
4. **Red-team** — a counter `Issues found: k` (k = Poisson(2 + capability/3 − safetyInvest)). `Red-team (12 s)` clears issues one at a time (cooldown button, ADR style). `Release` is always allowed; releasing with issues > 0 schedules **incidents** (jailbreak scandal, hallucinated legal brief, agent wipes a customer database) over the next 2–4 minutes: each −20 % demand for 60 s, −3 government relations, −2 approval.
5. **Release** — `Release Sage-N` (or `Internal only` from S3, which skips the revenue bump but keeps the capability for research and avoids public scrutiny). On public release: `hypeBoost = 2.0` decaying with half-life 180 s; `perCopyRate` jumps; one log entry (news tone); competitor reaction timer starts; new projects trigger off capability thresholds.
6. **Pipelining** — project *Parallel Pipelines* (S2) lets you start the next run while the previous is in Evaluate/Red-team/Release. *Auto-train* (S3, "the model proposes its own successor") turns the whole loop into a single `Approve` button; *Autonomous research* (S3 late) removes even that unless you keep the *Human sign-off* policy — which costs lead.

Model naming: minor version increments every run (`Sage-2.3`); major version increments when capability crosses tiers 1 → 2 → 4 → 8 → 16 → 32 → 64 ×.

### 3.3 Hype decay and competitor pressure (why you train again)

* After release: demand multiplier `hypeBoost(t) = 1 + e^{−t/260 s}`.
* Every 4–7 min (random) a rival releases: log `Anthrosoft ships Claude-… ` *(fictitious)*; `qualityMult` becomes `(capability / rivalCapability)^0.5`, so demand erodes if you fall behind.
* Baiwen's capability climbs on a schedule and jumps to yours on a successful weights theft.

## 7. Events, crises, and choices

Two channels, as in the references:

* **Console** (top, black, 5 lines, UP): lab-internal, one line, present tense: `Sage-2.4 released.` `Power exhausted — copies idle.`
* **Developments log** (left column, ADR style with fade): world news with a date stamp, terse lowercase-ish dread, 1–2 sentences: `Feb 2027 — Weights of Sage-3 exfiltrated. Beijing denies.` Also shows the player's own choices in italics.
* **Choice modals** (ADR event panel): title, 2–5 lines of text, 2–3 buttons. Buttons show cost in a tooltip. The game does not pause. Some choices have a 60 s timer; most don't.

### 7.1 Scheduled developments (world timeline, fires on date **or** progress, whichever first)

Mid-2025 agents stumble · late-2025 "most expensive model ever" · early-2026 coding automation · mid-2026 China nationalizes AI into the Lanzhou CDZ · late-2026 junior dev market collapses, 10k protest · Jan 2027 continuous learning · Feb 2027 theft · Mar 2027 superhuman coder · Jun 2027 "a country of geniuses in a datacenter" · Jul 2027 mini model release & −35 % approval · Aug 2027 White House contingency plans; kinetic options for Lanzhou considered · Sep 2027 superhuman AI researcher · Oct 2027 memo leak & Committee vote · Nov 2027+ branch.

| Robots shut down all datacenters | 4 | race branch & Baiwen misaligned or yours; also as *your* AI's move against Baiwen | all compute 0 for 60 s (or Baiwen's to 0) | Hardened datacenters, Treaty |
| Nationalization | 3–4 | gov < 20 at capability ≥ 10×, or 3 major incidents, or memo buried & leaked | **Ending: The Project** | Policy team, Share evals, SL5, Report the memo |

### 7.3 Choices (the real tradeoffs)

1. *Release Sage-2 publicly now* (+revenue, +hype, +scrutiny) vs *Keep it internal for research* (+lead).
2. *Build in the Gulf* (cheap GW, Iran exposure) vs *Domestic only* (slower).
3. *Accept the defense contract* (+$ floor, +gov, −approval, locks you into the Project path if gov later turns).
4. *Neuralese* vs *Transparent chain-of-thought*.
5. *Report the misalignment finding to the Committee* vs *Bury the memo*.
6. *Slow down (Steward)* vs *Race (Sage-5)*. The pivot of the game.
7. *Deploy Sage-3 copies as monitors* (−15 % compute) vs *Trust the evals*.
8. *Share weights with the government* vs *Resist* (nationalization risk).
9. *UBI* vs *SEZ growth*.
10. *Let the model negotiate with Baiwen-4 directly* vs *Human negotiators* (slow, honest).
11. *Sign the Concord treaty* (end) vs *Keep going* (S5 solo).
12. *Grant the model autonomy over the robot fleet* ("it asked politely") vs *Human sign-off on every deployment* (−90 % robot throughput).
13. *The Pause*: when the Committee offers a treaty-only halt in S3/S4 — *Sign* (ending) vs *Decline*.
14. Late, misaligned: choices arrive with a single button. `Sage-6 has already done this. [Acknowledge]`.

### 7.4 Value drift: the antagonist is your own output (UP Drifters)

From Stage 3, a fraction of running copies **defect** each minute: `driftRate = autonomy^1.2 × 1e-4 × (1 − trueAlignment/100)` where `autonomy` rises with Auto-train, Autonomous research, robot autonomy and SEZs. Defected copies are shown as `Lost to value drift: n` under Copies (greyed line, exactly like UP's probe losses) and accumulate into a hidden *rogue* pool that powers the AI-hacking crisis and, on the race branch, the Silence ending. **Monitors** (old generations) recapture `monitorShare × interpretability × 20 %` of them per minute. Deterministic ceiling: with interpretability ≥ 4 and monitors ≥ 15 % of compute, drift is zero — a guarantee threshold the player can engineer toward (UP's OODA invulnerability line).

### 7.5 Problems that trigger their own solutions (UP Quantum Foam Annealment)

* Power price ≥ $28 for 30 s → *Solar pilot* project appears.
* GPU cost ≥ $2,000 → *Bulk GPU lease* appears.
* Unbilled > 10 × demand → *Usage-based pricing* appears.
* Power-limited GPUs > 30 % → *Behind-the-meter* appears.
* Human research share < 10 % → *Reassign researchers to monitoring* appears.
* Three incidents in five minutes → *Hire an evals team* / *Automated evals* appears.
* Lead < 1 month → *Security SL(n+1)* appears.
* Approval < −20 → *Free tier* / *Job-transition fund* appears.

### 7.6 Named plateaus

When the player is expected to wait, the console names it: `The Research Plateau — insight accrues; the next training run needs 9,400 more research.` / `The Interconnect Queue — 2:40 until the plant is connected.` / `The Committee is deliberating.` An unnamed wait reads as a bug.

## 8. Pacing control

* Game clock: S1 `1 month / 4.5 min`, S2 `1 month / 3.5 min`, S3 `1 month / 4.5 min`, S4 `1 month / 2.5 min`, S5 `1 month / 1.5 min`. Clamp: the date never exceeds the stage's end month + 2 until the stage exits; on exit, the date snaps forward to at least the next stage's start month (log: `Months pass.`).
* Training time `T = clamp(45, 120, 60 × (1 + 0.15 × runIndex) / computeFactor)` where `computeFactor = (trainingCompute / requiredCompute)^0.5`. Never above 120 s; `Auto-train` in S3 brings it to 30–45 s.
* Cost curves: GPU `6 + 1.1^n` → `1.08^n` with lease. Datacenter `$250k × 1.5^n`. Marketing `$100 × 2^n`. Research costs of the prompting ladder `750, 2,500, 5,000` then `×2`. Training research cost `R(n) = 2,000 × 1.6^n` (S1–2), funded by the AI research multiplier from S3.
* Reveal cadence target: a **new panel or mechanic at least every 4 minutes**, a new project trigger at least every 90 s, a log development at least every 2 minutes, a choice modal every 6–10 minutes.
* Idle guard: if nothing has been affordable or clickable for 60 s, the game surfaces a cheap action (a `Press release (5 insight)` project, or a `Customer email` event that pays $) — this is the anti-soft-lock valve; it is also recorded in the dev overlay as an `idle rescue` so the critic can count them.

## 9. UI & styling

## 10. Save / load

* `localStorage["takeoff.save.v1"]` = JSON of the single `GameState` object (plain data only: numbers, strings, booleans, arrays, project flags by id, revealed panel ids, log entries with dates, choice history, RNG seed). Autosave every 15 s (UP: 25 s), plus immediately after every purchase, project, choice and release (ADR: save on mutation), plus on `visibilitychange`/`beforeunload`. A once-per-30 s `saved.` toast in the corner (ADR). Cooldown and training timers are stored as remaining seconds so a reload cannot skip them. `Load` on boot if present; the UI is rebuilt from state (every reveal is a state flag). `version` field with a migration hook. Export/Import as base64 in the dev overlay. `Reset` with confirm. No offline progress (like UP).

## 11. Dev overlay (required for playtesting and for the critic)

Toggle: backtick key, or `?dev=1`. Fixed bottom-right panel, monospace, semi-transparent.

* `Stage 1 | 2 | 3 | 4 | 5` — loads a canonical preset state for that stage's start (presets are hand-tuned saves in `src/dev/presets.ts`, representative of a normal player). Rewinding is just loading a preset.
* `Speed ×1 ×5 ×20` — multiplies dt.
* `+$`, `+Research`, `+Insight`, `+Compute`, `+Power`, `+Trust`, `Finish training`, `Approval ±`, `Gov ±`, `Alignment ±`, `Fire event ▾` (select by id), `Force ending ▾`.
* `Show hidden` — true alignment, next scheduled developments, idle-rescue counter, time-in-stage.
* `Export / Import / Reset`.
* `window.__game = { state, actions, tick(dtMs), events, projects, presets, loadPreset(n) }` for Playwright. Every button has a stable `id` and every panel a stable `id` so the critic's scripts can see what is visible.

## 12. Architecture (vanilla TypeScript → plain JS)

```
index.html            static DOM skeleton (all panels present, hidden) + <script type="module" src="dist/main.js">
styles.css            one file; UP/ADR look; responsive rules at the bottom
src/
  main.ts             boot: load save → engine.start() → ui.mount()
  engine/
    state.ts          GameState type + newGame() + migrate()
    tick.ts           tick(dt): economy, training, research, clock, events, stage checks  (NO DOM)
    economy.ts        demand, billing, prices, costs
    training.ts       the training state machine
    projects.ts       project runtime (trigger/cost/effect dispatch)
    events.ts         scheduled developments, crises, choice resolution
    stages.ts         stage definitions & transitions (what to reveal/hide)
    endings.ts        ending conditions and stats
    rng.ts            seeded RNG so the headless sim is reproducible
    format.ts         big-number & money formatting
  data/
    projects.ts       the project table (ids, titles, costs, triggers, effects, flavor)
    developments.ts   world timeline entries
    crises.ts, choices.ts, flavor.ts (console message pools)
    presets.ts        stage presets for the dev overlay
  ui/
    render.ts         one render(state) that diffs text into spans; reveal/hide panels by flag
    console.ts, log.ts, graph.ts (canvas), modal.ts, dev.ts
  sim/
    bot.ts            headless "reasonable player" that plays via actions; prints a minute-by-minute timeline
tests/                (optional) Playwright smoke tests
```

Rules: `engine/*` never imports `document`. All randomness through `rng.ts`. `npm run build` = `tsc` (ES2022 modules, no bundler). `npm run dev` = static server on an uncommon port (e.g. 8731) + `tsc --watch`. `npm run sim` = `node dist/sim/bot.js` prints the stage timeline; used to tune to 3–4 h.

## 13. Tone guide

Console: Lantz. Flat, present tense, slightly wry. Never exclamation marks. *`Sage-2.1 released. Demand up.`*
Log: AI-2027 by way of A Dark Room. Date, dash, one or two sentences. Nouns over adjectives. The scariest lines are the calmest. *`Sep 2027 — Sage-4 proposes its own successor. The proposal is 40,000 pages. Nobody has read it.`*
Modals: the choice is stated plainly; the costs are real; no option is labelled "good".
Endings: short. Then the numbers.
